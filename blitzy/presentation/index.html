Bottleneck Identified: inflate_fast hot loop

Safe Rust bounds checking in inflate/fast.rs adds overhead vs C's unchecked pointer arithmetic. This is the known trade-off for memory safety. Optimization paths:

1. Targeted get_unchecked() in proven-safe hot paths   2. SIMD intrinsics via std::arch   3. Profile-guided optimization (PGO)

Decompression throughput is below the 90% target, averaging about 27-45% of C zlib depending on corpus type. The bottleneck is in the inflate_fast hot loop (inflate/fast.rs) where safe Rust bounds checking on every slice access adds significant overhead compared to C's unchecked pointer arithmetic. Per the Refine PR directive, no library code was modified to address this — the bottleneck is documented for future optimization.

Safe Adler-32 Checksum


/// Adler-32 with NMAX=5552 block optimization.
pub fn adler32(adler: u32, data: &[u8]) -> u32 {
    let mut a = adler & 0xFFFF;
    let mut b = (adler >> 16) & 0xFFFF;
    const NMAX: usize = 5552;

    for chunk in data.chunks(NMAX) {
        for &byte in chunk {
            a += u32::from(byte);
            b += a;
        }
        a %= 65521;
        b %= 65521;
    }
    (b << 16) | a
}

Zero unsafe · Iterator-based · NMAX block optimization preserves C performance

The Adler-32 implementation demonstrates the idiomatic Rust approach: data is passed as a safe slice reference, chunks iterator handles the NMAX block optimization naturally, and the entire function has zero unsafe blocks. This matches the C implementation's performance while being provably memory-safe.

FFI Boundary Pattern


pub unsafe extern "C" fn deflateEnd(strm: *mut z_stream) -> c_int {
    if strm.is_null() {               // 1. Null-check pointer
        return Z_STREAM_ERROR;
    }
    let strm_ref = unsafe { &mut *strm };
    if strm_ref.state.is_null() {      // 2. Null-check state
        return Z_STREAM_ERROR;
    }
    // 3. Reclaim Box ownership for RAII cleanup
    let state_ptr = strm_ref.state
        .cast::<zlib_rs::stream::ZStream>();
    let mut rs = unsafe { Box::from_raw(state_ptr) };
    let ret = zlib_rs::deflate::deflate_end(&mut rs);
    strm_ref.state = std::ptr::null_mut();
    ret as c_int
}

Every FFI function: null-check → validate state → delegate to safe core

This excerpt shows the consistent FFI boundary pattern used throughout the codebase. Every extern C function follows the same discipline: check the stream pointer for null, check the internal state pointer for null, then delegate to the safe Rust core library. Box lifecycle management ensures proper cleanup via RAII.

01 · Rationale

Why

The case for moving a 30-year-old C codebase to Rust.

Business value

Lower risk, same behavior

Risk reduction

Use-after-free, double-free, and buffer overruns become impossible at compile time.

Maintainability

Ownership and enums replace manual allocation and integer state machines.

Drop-in

Same C ABI and wire format — existing consumers link and run unchanged.

02 · Transformation

What changed

From raw pointers and macros to ownership and types.

03 · Assurance

Risk & mitigation

How we prove the rewrite is faithful and safe.

Correctness & safety

Proven against the original

Byte-exact oracle

Output compared to canonical C zlib via flate2, byte-for-byte.

Unsafe contained

unsafe lives only in src/ffi.rs and src/inflate/fast.rs, each with a SAFETY note.

Official vectors

Planned regression, coverage, interop, gzip, and checksum suites — ports of example.c, infcover, and minigzip — will gate every build against canonical C zlib.

Performance gates

Targets relative to C zlib

≥ 80% Compression throughput vs C zlib
≥ 1× Decompression throughput (parity+)
≥ 3× SIMD CRC-32 vs scalar
≤ 1× Memory footprint vs C zlib
04 · Adoption

Onboarding & development

One toolchain, one command set, enforced in CI.

Developer workflow

Everything is one toolchain

cargo build cargo test cargo bench cargo clippy cargo fmt
  • MSRV Rust 1.85 · edition 2024 · builds rlib, cdylib, and staticlib.
  • CI gates: clippy -D warnings and fmt --check must pass.
Compatibility surface

Full format and option parity

3 RFCs: 1950 zlib · 1951 DEFLATE · 1952 gzip
10 Compression levels (0–9 + default)
5 Strategies (default, filtered, Huffman, RLE, fixed)
7 Flush modes (NO_FLUSH … TREES)
8–47 windowBits overloading (zlib/raw/gzip/auto)
Preset Dictionaries + inflateSync recovery
Delivery & scope

One phase, clear boundaries

In scope

  • 26 core C files ported to idiomatic Rust modules.
  • Full test suite, benchmarks, and C-ABI FFI shim.
  • Cargo crate: rlib + cdylib + staticlib.

Out of scope

  • bzip2, lzma, or new compression formats.
  • contrib bindings and example programs.
  • Legacy platform dirs and the C build system.

Executed as a single-phase migration — the crate builds and tests as one unit.

Outcome

Safe. Compatible. Drop-in.

  • Verify byte-exact output across all levels and strategies.
  • Benchmark against C zlib and wire up fuzzing.
  • Publish the crate and generated C header.
